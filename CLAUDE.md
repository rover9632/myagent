# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Minimal agent MVP: FastAPI + LangChain `create_agent` (vLLM OpenAI-compatible endpoint, Tavily search), Docker sandbox for code execution, PostgreSQL for users/sessions/conversation memory, SSE streaming, and a ChatGPT-style Next.js frontend in `web/`.

## Commands

```bash
uv sync                                          # install deps
uv run pytest -q                                 # full suite; needs NO live PG/Docker/LLM
uv run pytest tests/test_auth_api.py -q          # one file
uv run pytest -k test_login -q                   # pattern match
uv run ruff check .                              # lint (line-length 100; rules E,F,I,B,UP)

uv run uvicorn app.main:app --host 0.0.0.0 --port 8061   # backend (needs .env PG_URI + sandbox image)
docker build -t agent-sandbox:py312 ./sandbox-image        # sandbox image

cd web && npm install && npm run dev             # frontend on :3000
cd web && npm run build && npx eslint src        # frontend gates
```

`uv.lock` is gitignored on purpose — never commit it. `.env`, `data/`, `logs/` are also gitignored.

## Working agreements (developer's standing rules)

- The developer starts/restarts the backend themselves — do not launch or kill long-running servers here.
- Never edit `.env` or `web/.env.local` (secret files); update `.env.example` / `web/.env.example` instead, and never print secret values from them.
- Commit messages carry NO `Co-Authored-By` or similar attribution trailers.

## Backend architecture (app/)

- **Wiring is all in `main.py` lifespan**: `DockerSandbox.check_available()` → one psycopg3 `AsyncConnectionPool` (kwargs: `autocommit=True, prepare_threshold=None, row_factory=dict_row`) **shared by UserStore and AsyncPostgresSaver** → `build_agent(settings, sandbox, checkpointer)` → `app.state.{pool,user_store,agent_service,sandbox}` + hourly workspace-cleanup task. Startup fails fast (RuntimeError) when Docker or PG is unreachable; tables are created idempotently on boot (`CREATE TABLE IF NOT EXISTS` + saver `setup()`, no alembic).
- **Request flow**: `/v1/agent/chat/stream` → `require_user` dependency (session Bearer → `User`) → `AgentService.stream()` sets `username`+`thread_id` **contextvars** → LangGraph agent streams SSE events `start/tool_start/tool_end/token/error/done` (`start`/`done` echo the *client* thread_id).
- **Tools never receive user/thread as parameters**: `app/tools/execution.py` reads them via `app/context.py` contextvars (`get_username()`/`get_thread_id()`, both raise RuntimeError when unbound) and calls `sandbox.run(user=..., thread_id=...)`.
- **Memory namespacing**: checkpointer key is `f"{username}:{thread_id}"` — client-supplied thread_ids can't collide across users. The username regex `^[a-zA-Z0-9_-]{3,32}$` deliberately excludes `:` (keep it that way).
- **Auth split**: `user_store.py` = thin SQL layer over the pool (bcrypt via `asyncio.to_thread`; DB stores only sha256 of session tokens; 30-day TTL; unknown-username login burns a dummy `checkpw` against timing enumeration); `auth.py` = `require_user` dependency; `auth_api.py` = `/v1/auth/{register,login,logout,me}` router. There is no static API token anymore.
- **Two-level workspaces**: `data/workspaces/<user>/<thread>/`; both path segments go through `DockerSandbox._safe_thread_id` (sanitized + sha256 short-hash suffix). Containers only ever see the single thread dir mounted as `/workspace`. TTL cleanup deletes stale thread dirs, then `rmdir`s empty user dirs.
- **Uploads**: `app/uploads.py` (framework-free) saves chunked/capped files into `<workspace>/uploads/`; `ChatRequest.attachments` echoes are merged with a directory scan into a manifest note appended to the user message. An HTTP middleware in `main.py` early-rejects oversize bodies before form spooling.

## Frontend architecture (web/)

- **This is a Next.js 16 fork with breaking changes** (see `web/AGENTS.md`, regenerated by `next dev` — leave it alone): read `web/node_modules/next/dist/docs/` before writing route/config code. Route files must **not** export `runtime`/`dynamic` segment configs. `npm run build` may fail on the first attempt with a SecurityFatalError upgrade nudge — rerun the same command.
- **Backend has no CORS**: the browser only talks to same-origin proxies under `web/src/app/api/` which forward to `BACKEND_URL`. Proxies forward the browser's `Authorization` header **verbatim** (shared helpers in `lib/backend.ts`); the Next server holds no backend secret.
- `/api/chat` validates the request body **before** checking auth — `page.tsx`'s "configured" probe POSTs `'{}'` and relies on 422≠500. Don't reorder.
- `page.tsx` restores the session tri-state: valid → chat; 401 → clear token, show `AuthGate`; backend unreachable → **keep** the session. `ChatApp` is remounted per user via `key={username}`.
- localStorage keys: `myagent.auth.v1` (token+username) and `myagent.threads.<username>.v1` (per-user UI history only — authoritative memory lives in server-side PG checkpoints).
- 401 mid-stream/mid-upload finalizes the bubble and falls back to the login gate (`onUnauthorized`).

## Testing strategy

- pytest `asyncio_mode=auto`; API tests use `httpx.ASGITransport`, so **the lifespan never runs** — fixtures wire `app.state` manually (see `tests/conftest.py`).
- Test doubles in conftest: `FakeAgent` (scripted `astream_events`, records received config), `FakeSandbox` (tmp_path-backed, uses the real `_safe_thread_id`), `FakeUserStore` (in-memory, same contract incl. case-insensitive `authenticate`). The `logged_in(app, username)` contextmanager installs FakeUserStore + `dependency_overrides[require_user]`.
- Agent-endpoint tests use the override; `/v1/auth` endpoint tests exercise the **real** `require_user` against FakeUserStore via `app.state.user_store`.
- Real SQL/bcrypt are not covered by the suite (only by startup self-checks and manual smoke). `tests/test_sandbox_docker_integration.py` runs real containers and auto-skips without the daemon/image.

## Pinned versions & security cliffs (don't "fix" these)

- `langgraph-checkpoint-postgres>=3.1.2,<3.1.3` is load-bearing: 3.1.3+ forces `langgraph-checkpoint` 4.3.0, but this repo pins 4.2.0. After any dep change, verify `uv.lock` still resolves langgraph-checkpoint 4.2.0 (uv won't auto-downgrade transitive deps; use `uv lock --upgrade-package 'langgraph-checkpoint==4.2.0'`).
- bcrypt 5 raises `ValueError` on >72-byte passwords instead of truncating: register pre-rejects >72 **bytes** with 422 (model_validator in `schemas.py`; char limits ≠ byte limits for CJK), while login/verify must map it to 401/False — never 500.
